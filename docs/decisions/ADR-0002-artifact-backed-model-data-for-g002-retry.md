direct_go_gate: not_yet_executed
final_pi_go: not_authorized

## Context

G002 stopped before its first dynamic Gate because the pinned Pi checkout does
not track `packages/ai/src/providers/data/`, while the standard Pi AI offline
build validates and copies that generated directory. Pi's suggested
`hydrate:model-data` command fetches four mutable online catalogs. Its local
manifest authenticates generated outputs but does not pin or preserve those
raw inputs.

The published `@earendil-works/pi-ai@0.82.1` npm artifact is immutable by
version and integrity digest, contains the complete emitted model-data
directory, and identifies release commit
`b4f293684bba718d59cc1157679bcf6157b3a7f5`. The pinned source is 40 commits
later, but the relevant tracked catalog shards, validator/schema and package
build boundary are unchanged across that range.

## Decision

For one bounded G002 retry, obtain missing model data only from the integrity-
pinned npm artifact for `@earendil-works/pi-ai@0.82.1`, stage and inventory it,
and require the pinned source's own `check:model-data` validation before
building.

Retain Pi's standard emitted-package build boundary. Do not run the live model
generator and do not construct a partial/custom Pi AI emitted package.

## Consequences

- The retry can exercise Pi's declared standard package build without making
  current online provider catalogs part of the deterministic test input.
- Restored model metadata is release-era test support data. It is not evidence
  about current provider availability, model pricing or Policy effectiveness.
- Pinned-source validation is mandatory; provenance alone does not establish
  compatibility with the later source commit.
- A validation or build failure returns to architecture review and cannot
  silently trigger live hydration, a custom build, a Pi patch or another
  runtime.
- All downloaded/generated bytes stay under ignored `.runs/` paths.

## Rejected Alternatives

### Run `hydrate:model-data` directly

Rejected for this retry because its strict data-only path reads mutable live
responses and the generated manifest omits raw-source hashes or immutable
source revisions.

### Build only the Pi AI modules transitively needed by Agent Core

Rejected at this checkpoint because it would replace Pi's standard package
build with a project-defined partial boundary and weaken the meaning of the
public emitted-package Gate.

### Use the published Pi AI package as the runtime dependency without validation

Rejected because its `gitHead` is 40 commits behind the pinned AgentHarness
source. Only its model-data payload may be used, subject to pinned-source
validation.

## Not Decided

- Direct AgentHarness feasibility;
- final Pi or V0 architecture Go;
- future design of a raw-input-capturing model-data pipeline;
- any real-model or Policy measurement decision.
