# 1. 本文件负责什么

本文件规定第二项目如何使用：

- Pi；
- `cc-harness-knowledge`；
- `learn-claude-code`；
- SearchCLI；
- Youtu-Agent；
- SkillOS；
- OpenHarness；
- Harbor / Terminal-Bench；
- 其他成熟 Coding Agent 与 Harness 项目。

本文件专门纠正一种错误理解：

```text
个人贡献边界
=
只能抽象借鉴，不能接近成熟实现
```

正确原则是：

> **复用控制解决的是来源、许可证、适配和验证问题，不是原创纯度问题。**

---

# 2. 允许的复用方式

在许可证允许、当前 Goal 有明确需求、用户能够理解和解释的前提下，允许：

```yaml
allowed_reuse:
  direct_dependency: true
  direct_module_reuse: true
  module_porting: true
  cross_language_rewrite: true
  behavioral_reimplementation: true
  architecture_adaptation: true
  contract_or_schema_adaptation: true
  test_case_adaptation: true
```

具体含义：

## 2.1 Direct Dependency

直接依赖成熟包或 Runtime。

示例：

- Pi Agent Core；
- CLI Library；
- Git / Process Library；
- Schema Validator。

## 2.2 Direct Module Reuse

在许可证允许时，直接采用成熟项目中的相对独立模块，并进行必要适配。

## 2.3 Module Porting

将 Python、Go 或其他语言模块移植为 TypeScript。

## 2.4 Cross-language Rewrite

保留行为合同和核心数据流，用 TypeScript 重新实现。

## 2.5 Behavioral Reimplementation

不复制代码，但复现：

- Plan / Dry Run；
- Checkpoint；
- Candidate / Apply 分离；
- Experience Promotion；
- Trial Artifact。

## 2.6 Architecture Adaptation

将成熟项目架构重组到：

```text
Pi Runtime
+ TypeScript
+ Coding Agent
+ Environment Verifier
```

而不是照搬原项目全部结构。

---

# 3. 复用决策标准

一个模块是否值得复用，不以“是不是自己原创”为主要判断，而以以下问题判断：

```yaml
reuse_decision:
  solves_a_real_project_problem:
  reduces_low_value_reimplementation:
  fits_pi_and_typescript:
  fits_coding_agent_semantics:
  user_can_explain_the_contract:
  license_allows_intended_use:
  behavior_can_be_verified:
  does_not_expand_scope_without_value:
```

建议优先级：

```text
成熟模块直接采用
> 有界移植或重写
> 行为仿写
> 从零自研
```

只有以下情况优先自研：

- 现有实现与 Pi 架构冲突；
- 模块过重；
- 许可证不适合；
- 核心行为无法验证；
- 自研本身就是项目需要展示的关键能力；
- 适配成本高于最小实现。

---

# 4. 个人贡献的正确表达

个人贡献不等于“所有代码都从零写”。

高质量贡献可以是：

```text
识别真实问题
→ 搜索成熟实现
→ 理解其合同和边界
→ 选择复用方式
→ 移植到 Pi / TypeScript
→ 针对 Coding Agent 重构
→ 接入 Verifier / Trace / Eval
→ 证明适用范围与限制
```

简历和面试应明确区分：

| 层 | 来源 |
|---|---|
| Agent Loop / Provider / Session | Pi |
| 某个 Checkpoint 模式 | SearchCLI 或其他上游 |
| Rollout / Environment 概念 | Youtu-Agent / Eval 框架 |
| Skill 生命周期思想 | SkillOS |
| 项目适配、统一数据合同、Pi 集成、Verifier 和实验 | 本项目 |
| 结果验证与边界判断 | 本项目 |

# 8. 各来源的建议用途

## 8.1 Pi

### 定位

```text
主 Agent Runtime
```

### 可直接复用

- Agent Loop；
- Provider；
- Tool Calling；
- Session；
- JSONL；
- Context / Compaction 构件；
- Headless / Direct Harness；
- 基础 Tool。

### 本项目负责

- Pi Adapter；
- Task / Attempt；
- Workspace；
- Verifier；
- Outcome；
- Recovery；
- Rollout；
- Regression；
- Experience Candidate。

### 约束

- 固定 Commit；
- 默认不修改 Pi Core；
- 任何 Core Patch 需要单独 ADR 和证据；
- 不将 Pi 自带能力包装成项目原创。

---

## 8.2 `cc-harness-knowledge`

### 定位

```text
用户自建 Harness 知识库与设计审查材料
```

### 用途

- 提炼 Problem / Invariant / Failure Mode；
- 与 Pi 源码对照；
- 设计 Tool、Context、Session、Skill；
- 代码审查；
- 面试学习与复盘。

### 允许方式

- 直接转化为设计检查表；
- 形成 Skill / Policy Candidate；
- 对照 `learn-claude-code` 源码；
- 作为 Goal 的设计输入。

### 禁止误用

- 不证明 Pi 当前行为；
- 不自动形成 Feature Parity 清单；
- 不因 Claude Code 有某能力就自动创建 Goal。

---

## 8.3 `learn-claude-code`

### 定位

```text
可执行的 Harness 教学源码参考
```

### 允许方式

- 源码级阅读；
- 对照用户笔记；
- 移植小型独立模块；
- TypeScript 重写；
- 仿写上下文或工具结果模式。

### 重点候选

- Context Projection；
- Tool Result Handling；
- Session / State；
- Stop Policy；
- Skill / Workflow 表达。

### 约束

- 不照搬完整目录和功能；
- 每次研究必须对应当前具体模块；
- 记录采用与未采用部分。

---

## 8.4 SearchCLI

### 定位

```text
候选生成、实验执行和发布边界的工程案例
```

### 优先研究

- `plan`；
- Dry Run；
- 预算预估；
- Checkpoint；
- Resume；
- Candidate / Apply 分离；
- 长任务分解；
- 人工发布边界。

### 允许方式

- 直接移植通用模块；
- TypeScript 重写；
- 仿写 CLI 合同；
- 重构为 Coding Agent 语义。

### 不采用

- 不因其使用搜索优化算法，就自动采用 SPA 或种群算法；
- 不照搬搜索领域数据模型。

### 激活阶段

```text
V0 / V1
```

---

## 8.5 Youtu-Agent

### 定位

```text
V2 Rollout 与 V3 Experience / Promotion 的重点源码参考
```

### 重点研究

- Dataset；
- Environment；
- Rollout；
- Judge；
- Experiment Identity；
- Persistence；
- Experience / Practice；
- Candidate Improvement；
- Promotion。

### 允许方式

- 直接移植独立模块；
- Python → TypeScript；
- 重写数据合同；
- 抽取一个子系统；
- 与 Pi Adapter 重新组合。

### 激活阶段

```text
V2 设计前
V3 设计前
```

### 当前约束

不作为 V0 Charter 阻塞项。

---

## 8.6 SkillOS

### 定位

```text
V3 Skill / Curator / Related Task 的研究输入
```

### 重点吸收

- Frozen Executor / Curator 分离；
- External SkillRepo；
- insert / update / delete；
- Related Task Stream；
- Skill 紧凑性。

### 不采用

- Curator 强化学习训练；
- 模型参数更新；
- 训练专用 Curator。

### 激活方式

- 论文优先；
- 只有发现可直接复用的生命周期模块时再克隆源码。

---

## 8.7 OpenHarness

### 定位

```text
Permission / Preflight / Hook / Session 参考
```

### 触发条件

只有当前 Goal 进入以下问题时，本地固定源码：

- Permission；
- Preflight；
- Dry Run；
- Hook；
- 某个具体 Session / Context 模块。

### 当前不做

- 不为了“比较成熟 Harness”而全面克隆和复刻；
- 不让其替代 Pi；
- 不构建 Pi + OpenHarness 双 Runtime。

---

## 8.8 Harbor / Terminal-Bench

### 定位

```text
任务、环境、Agent Adapter、Trial、Verifier、Artifact 的 Eval 框架参考
```

### 触发条件

- V1/V2 任务和 Trial 规模开始显著增加；
- 自研 Runner 出现重复；
- 需要标准环境或 Agent Adapter；
- 需要公开 Benchmark 兼容。

### 当前不做

- 不在 V0 提前引入完整框架；
- 不让 Benchmark 接管项目产品身份。

# 10. 许可证与合规

任何直接代码复用或移植前必须确认：

- License 类型；
- Attribution 要求；
- Notice / Copyright；
- 是否允许修改、分发；
- 是否与项目最终发布方式兼容。

许可证不明确时：

```text
暂停直接复制
→ 可继续研究公开行为与接口
→ 等确认后决定移植或重写
```

不得假设“开源仓库”自动等于可以任意复制。

---

# 11. 代码审查要求

所有移植或重写模块必须通过：

1. 类型检查；
2. 单元测试；
3. 与原行为的最小对照；
4. Pi / TypeScript 环境适配测试；
5. 当前项目真实场景测试；
6. 失败和限制记录。

如果是行为仿写，应明确：

- 哪些行为保持；
- 哪些行为删除；
- 哪些行为因 Coding Agent 语义而改变。

---

# 12. 防止上游反客为主

成熟项目只能服务当前问题，不能重写项目身份。

出现以下情况应暂停：

- 为迁移一个模块引入整个大型框架；
- 为了复用而改变 Pi 主 Runtime；
- 为匹配上游目录重构整个仓库；
- 上游抽象比当前需求更复杂；
- 上游模块要求提前实现 V3/V4；
- 参考项目成为项目叙事主体；
- 项目最终看起来只是多个仓库的 Glue。

判断问题：

> 移植后，第二项目的核心闭环是否更清晰、更可靠、更容易验证？

若否，应拒绝或缩小移植范围。

---

# 13. 防止“原创纯度”反向浪费

以下工作通常不应从零重复实现，除非有明确展示价值：

- 通用 CLI 参数解析；
- JSON / YAML Schema；
- Hash / ID；
- Process Wrapper 基础部分；
- Git 操作基础封装；
- Checkpoint 序列化；
- 通用 Report 模板；
- 文件遍历和 Diff 解析；
- 标准 Task / Trial Artifact 结构。

项目更应投入：

- Pi 集成；
- Environment Verifier；
- Failure Packet；
- Session Strategy；
- Multi-path Recovery；
- Path Selection；
- Experience Candidate；
- Related Task / Regression；
- Promotion / Rollback。

---

# 14. Codex 研究上游时的标准任务

每次上游研究必须有界：

```yaml
upstream_research_task:
  current_project_problem:
  target_source:
  target_commit_or_version:
  exact_modules:
  questions_to_answer:
  allowed_actions:
    - read
    - compare
    - port
    - rewrite
  expected_output:
    - source_map
    - adaptation_decision
    - implementation_candidate
    - rejected_parts
  stop_condition:
```

禁止创建：

```text
全面研究所有 Harness
全面比较所有 Coding Agent
复制全部成熟功能
```

# 17. 最终原则

```text
能直接采用成熟能力时，不为了原创而重复开发。
能有界移植时，不为了抽象纯洁只写概念报告。
能用实验证明适配价值时，不靠来源名气决定采用。
```

项目贡献的核心不是“每行代码都原创”，而是：

> **把成熟能力选择、移植并重组到 Pi / TypeScript Coding Agent 场景中，用环境 Verifier、受控实验和真实 Failure 证明它们何时有效、何时无效，以及如何支撑 Adaptive Harness 的完整闭环。**
