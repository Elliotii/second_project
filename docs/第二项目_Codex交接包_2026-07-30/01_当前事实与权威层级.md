# 4. G001–G006 的证据链

## 4.1 G001：固定 Pi 静态源码审计

已经证明：

- `@earendil-works/pi-agent-core` 公共包根导出 `AgentHarness`、Session、Tool 和相关类型；
- Direct `AgentHarness` 可以显式注入 Model、Thinking、Tools、Session、System Prompt 和 `NodeExecutionEnv`；
- Direct 路径不依赖 TUI 才能构造和执行；
- 可以观察 Provider、Message、Tool、Turn、Agent、Save Point 和 Settled 生命周期；
- Session 支持 JSONL、消息、配置、Branch、Compaction、Custom Entry 等机制；
- Direct 路径不提供完整 Sandbox、Exactly-once Tool Effects 或完整 Durable Runtime。

G001 结论：

```text
ACCEPT_FOR_DYNAMIC_VERIFICATION
```

没有证明 emitted package、真实 Provider 或恢复 Policy 效果。

## 4.2 G002：首次动态 Gate 受阻

阻塞原因：

- 固定 Pi 源码缺少标准构建所需的生成后 model-data；
- 这是 Build / Release Artifact Boundary，不是 AgentHarness、Tool Loop 或 Session 的运行失败。

G002 结论：

```text
BLOCKED_G002_SETUP
```

既不是 Pi Go，也不是 Pi No-Go。

## 4.3 G003：确定性 Direct Harness Spike

已经证明：

- 使用完整性固定的 npm Artifact 可以恢复 model-data，并由固定源码校验；
- 标准 `pi-ai` 和 `pi-agent-core` emitted package 可以构建；
- 公共 emitted import 可用；
- Faux Provider 下可运行 Baseline 与 Candidate；
- Baseline 只观察 Verifier；
- Candidate 在首次 Verifier 失败后获得结构化反馈并在同一 Harness / Session 中执行一次有界恢复；
- Manifest、Journal、Session、Verifier 和 Outcome 可以关联；
- Baseline / Candidate 初始 Workspace 和配置可以保持等价；
- Pi Core patch 数量为 0。

G003 结论：

# 7. 当前对 Pi 的事实性判断

## 7.1 Pi 的正确角色

当前最合理的分层是：

```text
Pi Agent Core
  → Model / Provider / Agent Loop / Tool / Message / Session / Runtime Events

Project Pi Adapter
  → 固定 Pi 配置、公共 API 适配、事件投影、上游隔离

Adaptive Harness / Workbench
  → Task / Workspace / Strategy / Verifier / Budget / Outcome
     / Recovery / Rollout / Regression / Experience
```

Pi 是 Agent 执行引擎，不是完整 Workbench。

## 7.2 Direct AgentHarness

事实支持：

- 公共导出；
- 非 TUI；
- 可注入；
- 可订阅；
- 可控制；
- G003/G006 已动态验证；
- 无 Core Patch。

当前判断：

```yaml
direct_agentharness:
  status: strongest_V0_runtime_candidate
  final_permanent_freeze: false
  recommended_next_action: freeze_V0_scope_in_version_charter
```

## 7.3 SDK 与 RPC

```yaml
pi_coding_agent_sdk:
  status: later_compatibility_option
  current_primary_runner: false

rpc_process_adapter:
  status: conditional_option
  activation_trigger: concrete_process_isolation_need
```

## 7.4 Pi 已知边界

当前已知但未自动升级为 Goal：

- 跨进程 settled Session 重建未动态验证；
- in-flight Provider / Tool 无完整恢复；
- Tool Side Effect 与 Result 持久化不构成 Exactly-once 事务；
- Direct 路径缺少完整自动 Context Policy；
- Workspace 控制不等于安全 Sandbox；
- 公共 Event API 存在实际语义陷阱；
- model-data 是构建和供应链边界；
- Pi Upstream 升级需要重新审计 Adapter 和行为。
